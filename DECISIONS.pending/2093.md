# Clusters under test run without request flow control

Proposed by story 2093, 2026-11-06.

**What was wrong.** `Camunda8RetriesOfTheListenersVanillaBpWritesIT.aFailingStartIsTriedOnce` failed
on a pull request which changed only documentation (run 42223156559, line 8.10). The test starts a
workflow with the plain client, right after an application boot. That boot opened 128 workers in
the same moment. A broker limits the requests it works on at the same time, and the limit starts at
100. The broker refused part of the workers with HTTP 503 and `RESOURCE_EXHAUSTED`. The client
repeats a refused request once, a second later. The command of the test was refused the second time
as well, and the client handed the 503 to the test. No adapter code was on that path.

**The rule now.** `ClusterUnderTest` starts every cluster with
`ZEEBE_BROKER_FLOWCONTROL_REQUEST_ENABLED=false`. A test about something else no longer depends on
how busy the cluster is in that moment. A wait or a repetition in each test would not fix this:
many tests send commands with the plain client.

`Camunda8TheClusterUnderTestTakesABurstIT` sends 400 requests at once to a fresh cluster and expects
no refusal. A cluster ignores a key it does not know. So this test is what tells us when a new line
stops reading the key. The newer key `CAMUNDA_PROCESSING_FLOWCONTROL_REQUEST_ENABLED` is ignored on
line 8.8, so it cannot replace this one yet.

**What this costs.** No integration test meets a real refusal by chance any more. These answers are
tested without a cluster:

- the commands a job handler sends back, in `Camunda8CommandRetryTest` and
  `Camunda8OutcomeCommandRetryTest`
- a phase-two command, which the outbox repeats, in `Camunda8ErrorsTest`

Two paths have no retry and no test with a 503: the pre-commit check of a task (phase one) and the
deployment at boot. There a refusal reaches the caller. This was so before this decision. It is a
question of its own, and this decision does not answer it.

**Where it is referenced.** The javadoc of `ClusterUnderTest#REQUEST_FLOW_CONTROL` and of
`Camunda8TheClusterUnderTestTakesABurstIT`.
